# AUTO EXPORT MVP 要件定義書（スコープ確定版）

版：2026-08-13 ／ 位置づけ：**固定額（400,000円）の対象範囲を確定する要件定義書**

## 1. 本書の位置づけ・費用と範囲の原則
- 本書に定義する機能範囲を **AUTO EXPORT MVP** とし、**固定額 400,000円** の対象とする。
- **本書の範囲内**：細かな微修正・内容/表現/文言の変更は **無償**。
- **本書の範囲外**：本書に明記のない機能は **「追加実装」として別途見積・別途スケジュール**。
- スコープ（機能の増減）の変更は、本書の改訂と相互合意で管理する（第10章）。
- 開発想定期間：**MVP 4〜5週間**（既存機能を大きく流用する前提の集中開発）。

## 2. 目的・全体像
海外輸出案件を「**1台＝1枠（GADGET）＝1加盟者**」で、参加・資金・進捗・精算まで一元管理する追加モジュール。
- 3者：**EXPORT PARTNER**（現地需要リサーチ・案件組成）／**CARBEY HQ**（承認・公開・資金/精算管理）／**MEMBER**（閲覧・ENTRY・進捗/精算確認）。
- 業務フロー：組成 → 本部承認 → 対象加盟者へ公開/通知 → ENTRY → 資金予約 → 輸出 → ガジェット単位精算 → 出納反映。
- 共有デッキ（100点版営業資料）の内容と整合（ファンドコントロール・可視化・1台精算・参加スタイル）。

## 3. スコープ（MVPに含む機能）
1. **ロール・権限**：EXPORT_PARTNER 新設、権限キー（下記）、最小権限、有料フラグ、外部パートナーのデータ隔離。
2. **案件・可変ガジェット**：案件（コンテナ）作成/編集、ガジェットの追加/削除/車種変更、枠取得（本部/パートナー）、募集停止。
3. **1台＝1枠＝1加盟者**：画面制御＋**DB制約**で保証。
4. **公開・通知**：`AUTO_EXPORT_ACCESS=ON` の加盟者のみに表示、対象者だけにチャット通知（通知→案件/ガジェットへ遷移）。
5. **ENTRY＋資金**：利用可能残高判定、**ガジェット確保と資金予約を原子処理（1トランザクション）＋排他**、資金不足表示。
6. **ファンドコントロール**：TOTAL／RESERVED／USED／**AVAILABLE**（横断残高）。入金確認後の再計算。
7. **有料「輸出車両選択」**：`EXPORT_VEHICLE_SELECT`（有料フラグ）で、**既存の検索機能を流用**し条件内候補を選定・提案（**本部承認制**）。
8. **輸出状態管理**：状態機械（第6.5）。START EXPORT 以降の進捗表示（**簡易**）。
9. **輸出完了・精算**：実績入力 → **ガジェット単位で損益算出 → 預かり金相殺 → 出納反映 → SETTLED**。未使用予約資金の解放。
10. **精算の取消・再精算**：**履歴を保持**（上書きしない）。
11. **監査ログ**：案件/ガジェット/ENTRY/資金/輸出/精算の主要操作を記録。
12. **多言語**：**日本語・英語の2言語**（文言外出し、パートナー画面を中心にEN対応）。

## 4. スコープ外（フェーズ2／別途見積）

- **決済システムとの自動連携**（有料権限の自動ON/OFF）。※将来対応できる構成にはする。

- 外部オークション／在庫API連携。
- **現地語（日英以外）**。
- 本書に明記のないその他機能全般。

## 5. ロールと権限
| ロール | 主体 | 概要 |
|---|---|---|
| EXPORT_ADMIN | 本部 | 全案件管理・承認・輸出開始/完了・精算（本部adminに権限付与でも可） |
| EXPORT_PARTNER | 外部パートナー | 案件組成・車種/台数設計・入力補助（**他加盟者の機密は閲覧不可＝データ隔離**） |
| 通常加盟者 | 加盟者 | 案件閲覧・ENTRY・進捗/精算確認（自分の参加枠のみ） |
| 有料加盟者 | 加盟者 | 上記＋輸出車両の検索・選定・提案（本部承認制） |

権限キー：`AUTO_EXPORT_ACCESS`（許諾者ON）／`EXPORT_PROJECT_ENTRY`（ENTRY）／`EXPORT_VEHICLE_SELECT`（有料・既定OFF）／`EXPORT_ADMIN`（本部）。
方針：**必要な機能のみ許可（最小権限）**。既存の権限マトリクス＋加盟者フラグに載せる。有料は初期は本部が手動ON。

## 6. 主要機能要件
### 6.1 案件組成（PARTNER）
入力：輸出先国・港／車種・条件／必要台数／ガジェット数／予算・必要資金／出港・到着予定／備考。→ 本部へ申請 → 承認で公開。
### 6.2 コンテナ・ガジェット
案件(1)–ガジェット(N)。ガジェット＝車種条件／必要資金／状態／参加者（member/hq/partner）／車両（**既存の車両を参照**）／精算コンテキスト。枠操作：募集継続/停止・車種変更・削除・本部取得・パートナー取得・別案件振替。
### 6.3 公開・通知
`AUTO_EXPORT_ACCESS=ON` の加盟者のみ表示＋チャット通知。通知から案件詳細・各ガジェットへ遷移。
### 6.4 ENTRY・資金
- 条件：**AVAILABLE ≥ 必要資金**。**AVAILABLE = 残高 −（有効予約：輸出＋自動売買＋半自動）−（仕入中の未精算コミット）**。
- 原子処理：ガジェット確保＋資金予約を **1トランザクション**、行ロックで排他（**1枠1加盟者はDB制約**）。
- 資金不足：不足額表示・ENTRY無効・入金確認→台帳反映で再判定。
### 6.5 輸出・進捗
状態機械：DRAFT → OPEN → RESERVED → FILLED（HQ_FILLED／PARTNER_FILLED）→ PURCHASED → EXPORTING → ARRIVED → COMPLETED → SETTLED ／ CANCELLED。START EXPORT 以降は進捗表示（簡易）。加盟者は自分の参加枠に必要な情報のみ閲覧。
### 6.6 精算
実績入力：売却額・車両原価・国内関連費・輸出関連費・現地関連費・その他。→ ガジェット単位で損益算出 → 預かり金相殺（台帳）→ 出納反映 → SETTLEDロック。未使用予約資金は解放。**取消・再精算は履歴保持（上書きなし）**。
### 6.7 多言語
日英2言語。文言を外出し。パートナー画面を中心にEN対応。

## 7. データ設計（要点）
- **既存流用**：members／預かり金台帳（`member_ledger`/`ledger_entries`）／費用・損益整合（案件×費用）／権限マトリクス（`role_permissions`）／通知／監査ログ／在庫・市場検索。
- **新規**：`export_projects`／`export_gadgets`／`fund_reservations`（横断予約）／（必要に応じ）翻訳テーブル。
- **原子ENTRY**：plpgsql `export_entry_reserve`（行ロック＋AVAILABLE判定＋予約）。
- **1枠1加盟者**：`export_gadgets` の部分ユニークインデックス（status=reserved/filled で member 一意）。

## 8. 非機能・前提
- 既存カーベイHD基盤を最大流用。環境は既存と同一（Vercel＋Supabase）。
- 日英対応・データ隔離・監査ログを標準実装。
- 金額・費用項目・状態名は運用に合わせ調整可能な構造（スコープ＝機能の増減は変更管理に従う）。

## 9. 成果物・完了条件（受け入れ基準）
- 第3章のMVP機能が動作すること。
- 主要E2Eシナリオが通ること：**案件組成 → 本部承認 → 公開/通知 → ENTRY（資金判定・原子予約・排他）→ 輸出状態遷移 → 実績入力 → ガジェット単位精算 → 預かり金相殺・出納反映（SETTLED）**。
- 権限・データ隔離が機能。日英表示。主要操作の監査ログが記録される。

## 10. 変更管理（重要）
- **範囲内**：微修正・内容/表現/文言変更＝**無償**。
- **範囲外**：本書に明記のない機能＝**「追加実装」として別途見積・別途スケジュール**。
- **スコープ変更**（機能の増減・第4章からの移動等）：本書を改訂し、相互合意のうえ反映。

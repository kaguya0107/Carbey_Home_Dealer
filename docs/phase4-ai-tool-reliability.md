# Phase4 AI ツールの信頼性テストと対応（2026-08-11）

デプロイ前の包括テストで、AIの市場データツールの精度を実データ＋ライブLLMで検証した結果と対応。

## テスト結果サマリ
中核（相場概況・地域比較・人気色・価格分布・課金・権限・拡張ゲート）は本番品質で正確。
一部の市場ツールが、データソースの問題で誤解を招く回答を返していた。

### 正確（検証済み・そのまま提供）
- `get_market_overview`：30日ローリング。プリウス1,936件・中央182万＝実データ一致。
- `get_popularity` / `get_price_distribution`：head countで正確な総数、サンプルで分布。
- `compare_regions`：地域別の件数・中央価格・人気色。
- 使用量メータリング（原子消費・枯渇・繰越）、実効config解決、拡張ゲート＝全て正確。

### 検出した問題
1. **成約/回転が空データ**：`sold_estimations`・`market_turnover` が0行 → `count_sold_recent`/`get_turnover_days`/`get_sold_breakdown` が「0」を事実のように回答。
2. **急上昇/トレンドがアーティファクト**：`get_rising_models`・`get_*_trend` が `market_daily_metrics` の分割取得・隣接2日比較で「NX +476%」等の見かけ上の変化を推薦。2ヶ月前の古い点も混在。
3. **絞込クエリが最新1runのみ**：`get_popularity`/`get_price_distribution` の絞込が最新1run（1県×数メーカー）だけを参照 → 例：プリウス神奈川2020+ が0件。
4. **色/価格帯の重複表示**：MVの地域別行を横断マージせず、同一色が重複。

## Part1（実施済み・デプロイ可）
- **信頼できるサブセットに限定**：会員公開ツールを `get_market_overview` / `get_popularity` / `get_price_distribution` / `compare_regions` の4つに限定（`MEMBER_MARKET_TOOL_NAMES`）。
- **絞込パスを30日ローリングへ統一**：`recent_market_observations` を head count＋サンプル集計に変更（最新1run依存を撤廃）。→ プリウス神奈川2020+ が 0→266 に修正。
- **重複マージ**：色・価格帯をキーでマージ。→ プリウス人気色 1,938件で実データ一致・重複解消。
- ライブLLM確認：成約質問には「掲載・市場の動きであり成約数ではない」と誠実に説明（0を断定しない）。
- 除外ツール自体は残置（TOOLS内）。本部AI・将来復帰のため削除はしない。

## Part2（根治・収集の平準化に依存）
成約/回転/トレンドの不正確さは**クエリのバグではなく、現状の分割スクレイピングに起因**する：
- VPSは県ごとに巡回するため、次runで対象外の県の掲載は「消失」扱いになる → 直近30日で `disappeared` が **約619,000件**（実際の成約数を大幅に超過＝偽陽性）。このため成約推定（`sold_estimations`）は成立せず空。
- 同じ理由で日次メトリクス（`market_daily_metrics`）は部分取得のノイズを含み、トレンド/急上昇が不安定。

→ 根治には **収集の平準化が前提**：
1. **収集を規則化**（P2「収集設定」で対象県×メーカーを常時再取得＝like-for-like比較が成立する巡回に）。[[market-snapshot-collection-architecture]]
2. その上で **成約推定を再構築**（同一スコープの連続runで消失＝成約を判定）、`sold_estimations`/`market_turnover` を再生成。
3. **トレンド系を日単位で集約**（criteria_hash横断でマージ・部分run除外・移動平均）して再構築。
4. 精度検証後、除外した4ツール（成約/回転/急上昇/トレンド）を `MEMBER_MARKET_TOOL_NAMES` に戻す。

※ 実収集・集計はVPS/分析サイト側の領域。分析サイトの「コード」は変更しない方針のため、Part2は収集規則化の判断とセットで別途着手する。
